# AGENTS.md

## Cursor Cloud specific instructions

### Environment

- **Android SDK** is installed at `$HOME/android-sdk`. `ANDROID_HOME` is set in `~/.bashrc` and `local.properties` is auto-generated by the update script.
- **JDK 21** is pre-installed (system OpenJDK). The project's `jvmToolchain` is set to 21.
- **Node.js 22 + pnpm 10** are pre-installed for the Vue 3 web frontend in `modules/web/`.

### Android app (`:app`, `:modules:book`, `:modules:rhino`, `:baselineprofile`)

- Build/test/lint commands are documented in `CLAUDE.md` — refer to that file for the full list.
- `compileSdk = 37` requires the `platforms;android-37.0` SDK package (note the `.0` suffix — the sdkmanager package name differs from the integer used in `build.gradle.kts`).
- The baseline profile module also needs `platforms;android-36` and `platforms;android-36.1`.
- One unit test (`ClickActionConfigDialogTest.kt`) depends on Robolectric which is not in the project's Gradle dependencies. Running `./gradlew test` will fail at compile time due to this. The other 6 test files are fine but cannot be run independently because Gradle compiles all test sources together.
- `./gradlew lint` will find ~17 pre-existing errors and ~1299 warnings. This is a known state of the codebase and does not indicate a regression.
- No signing keystore is needed for debug builds. Release builds require signing config properties in `gradle.properties` (see CI workflow).

### Web frontend (`modules/web/`)

- Run `pnpm install` then `pnpm dev` to start the Vite dev server on port 8080.
- `pnpm type-check` runs `vue-tsc`. `pnpm lint:fix` runs ESLint (3 pre-existing `@typescript-eslint/no-explicit-any` errors).
- The web frontend connects to the Android app's built-in HTTP server (Ktor). Without the app running on a device/emulator, the web UI will show a connection warning — this is expected in a headless dev environment.
- pnpm 10 may warn about ignored build scripts for `esbuild`, `@parcel/watcher`, `vue-demi`. Vite still works correctly despite these warnings.

### What cannot be tested in Cloud VMs

- **Connected/instrumented Android tests** (`./gradlew connectedAndroidTest`) require a running Android emulator or device, which is not available.
- **Running the Android app itself** requires an emulator/device. The "hello world" for the Android side is verified by a successful `assembleAppDebug` producing APK files.
